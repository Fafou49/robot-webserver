Ce document réunit deux choses qui bougent au fil du projet : le plan des réseaux WiFi sur lesquels vivent les deux Raspberry Pi, et la façon dont le code qui fait avancer le robot est organisé et s'enchaîne. Il est destiné à être mis à jour à mesure que le câblage réseau et le dépôt évoluent.

1.Plan réseau

Le développement se fait sur deux sites physiques, chacun avec sa propre box internet. Le rôle des deux Raspberry Pi est le même des deux côtés : la n°1 est embarquée dans le robot, la n°2 sert d'interface web pour lui envoyer des ordres.

liaison WiFi confirmée protocole ou adresse encore à définir

2.Organisation du code du robot

Le dépôt github.com/Fafou49/robot contient uniquement le code embarqué sur la Raspberry Pi n°1 (le robot). Le serveur web Flask de la Pi n°2 vivra dans un second dépôt, séparé. À l'intérieur, les fichiers sont classés par fonction plutôt qu'à plat :

robot/
├── motor_control/         pilotage moteurs (GPIO/PWM) et manette
│   ├── pwm.py
│   └── remote_control.py
├── pid/                   asservissement distance / cap
│   ├── pid_controller.py
│   ├── simulate_pid.py            (simulateur 1 boucle)
│   └── simulate_motor_commands.py (simulateur distance+angle -> PWM)
├── gps/                   lecture GPS, correction DGPS, calculs géo
│   ├── gps_parse.py
│   ├── gps_transfer.py
│   ├── dgps_transfer.py
│   └── gps_delta.py
├── archive/               anciennes versions (2025) gardées pour référence
├── tests/                 tests automatisés (pytest)
├── requirements.txt
└── .env.example           identifiants NTRIP (jamais commités)

La chaîne de commande, en un pipe Unix

Les trois programmes qui font avancer le robot ne s'appellent pas entre eux : ils s'enchaînent en pipe, chacun lisant la sortie du précédent sur son entrée standard.

python3 gps/dgps_transfer.py | python3 pid/pid_controller.py | python3 motor_control/pwm.py

3.Réglage des PID — résultats de simulation

Avant tout test sur le robot réel, les coefficients kp/ki/kd ont été comparés hors ligne avec deux simulateurs qui font tourner la vraie classe PIDController (pas une copie) : simulate_pid.py pour une boucle isolée, et simulate_motor_commands.py pour voir l'effet combiné distance + angle sur les commandes moteur.

Coefficients actuellement en place

Bouclekpkikd
Distance100.5
Angle0.501

Valeurs retenues parce qu'elles ne saturent pas et ne dépassent pas la cible sur le modèle simulé — à confirmer sur le robot réel, à basse vitesse, avant un usage complet en extérieur.
