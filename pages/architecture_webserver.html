Architecture du site web

Vue d'ensemble des fichiers du projet robot-webserver (Raspberry Pi n2) et de leurs dependances, cote code comme cote reseau. Cette page decrit le site ; voir le protocole de controle pour le detail des trames echangees avec le robot.

Schema general des dependances

Deux zones : ce que ce depot fait tourner sur la Pi n2, et ce a quoi il parle sur la Pi n1 (depot robot, documente separement). Une fleche pleine = import Python direct ; une fleche en pointilles = appel reseau.

Raspberry Pi n°2 — ce depot (robot-webserver)
.env / .env.example —configure→ app.py
→ importe robot_link.py → importe nmea.py
→ sert (statique) pages/*.html
→ sert (statique) media/videos/, media/images/
generate_password.py —alimente (manuel)→ .env
TCP 5050 (robot_link.py) ↓
HTTP 8000, route /media/camera (app.py) ↓
Raspberry Pi n°1 — depot "robot" (documente a part)
link/server.py camera/stream_server.py

nmea.py est une copie volontaire de link/nmea.py du depot robot (les deux projets se deploient independamment) — a garder synchronisee si le format des trames change, voir la page protocole.

Fichiers de l'application

Coeur du site (racine du depot)

FichierRole
app.py Application Flask principale : toutes les routes (/login, /control, /pages, /api/send, /media/*), generees en HTML inline (pas de dossier templates/). Gere l'authentification par session, relaie les commandes de la console vers le robot via robot_link.send_command, et proxy le flux camera en direct depuis camera/stream_server.py. La page /control (bandeau d'etat, console a deux onglets Console/TCP, boutons de commande) y est entierement construite cote serveur puis animee en JavaScript. C'est le point d'entree unique du site : les autres modules ne sont jamais charges que par lui.
robot_link.py Client TCP minimal : ouvre une connexion vers link/server.py (Pi n1), envoie une trame, lit une ligne de reponse, ferme. Utilise par app.py dans la route /api/send, elle-meme appelee par la console et par le sondage automatique du bandeau d'etat. Construit la trame via nmea.build_sentence et l'analyse via nmea.parse_sentence. Retourne toujours un dictionnaire avec au moins ok et sent, jamais d'exception laissee remonter jusqu'a Flask.
nmea.py Construction et analyse des trames $PROV,...*hh : build_sentence, parse_sentence, calcul du checksum XOR. Copie exacte de link/nmea.py du depot robot, sans dependance externe. Utilise uniquement par robot_link.py. Voir la page protocole pour le format complet.
generate_password.py Script a lancer a la main (python3 generate_password.py) pour obtenir la valeur de WEBSERVER_PASSWORD_HASH. Demande le mot de passe deux fois au clavier (jamais affiche), le hache avec werkzeug.security.generate_password_hash, et affiche la ligne a coller dans .env. N'est importe par aucun autre fichier du projet ; le mot de passe en clair n'est jamais ecrit sur disque.
requirements.txt Liste des dependances Python du site : flask, python-dotenv, requests. Installe avec pip install -r requirements.txt. Volontairement courte — contrairement au depot robot, ce site n'a pas de dependance materielle (GPIO, camera, port serie).
.env / .env.example Configuration d'execution, jamais versionnee pour .env (identifiants, cle de session) — .env.example sert de modele commente. Lu au demarrage par app.py via load_dotenv() : identifiants du site, adresse/port du robot (ROBOT_HOST/ROBOT_PORT) et de sa camera (CAMERA_PORT/CAMERA_STREAM_PATH).
.gitignore Exclut .env (secrets), venv/ et les caches Python (__pycache__/) du depot Git. N'a aucun effet a l'execution, uniquement au moment des commits.

Pages statiques (pages/)

Servies telles quelles par app.py (route /pages/<fichier>, sans templating) pour ne jamais casser leur propre HTML/CSS ; elles apparaissent automatiquement dans la liste /pages des qu'un fichier .html est depose dans ce dossier.

FichierRole
protocole_controle.html Reference vivante du protocole de commande du robot (trames NMEA proprietaires $PROV,...) : types de trames, exemples, checksum. Mise a jour a chaque evolution du protocole cote link/server.py du depot robot.
rapport_rover_dgps.html Rapport de projet autonome (schemas reseau des deux sites, organisation du code robot, pipeline DGPS/PID/PWM, courbes de reglage PID). Genere a un instant donne, pas mis a jour automatiquement avec le reste du code.
architecture_webserver.html Cette page — schema des dependances et role de chaque fichier de robot-webserver. A completer a chaque fichier ajoute ou retire du depot.

Contenus multimedia (media/)

DossierRole
media/videos/ Videos (.mp4/.webm/.ogg/.mov) jouees en boucle une a la fois dans le panneau "Video feed" de /control, uniquement quand le flux camera en direct n'est pas disponible. Vide par defaut (juste un .gitkeep) — affiche alors un emplacement "coming soon".
media/images/ Images (.jpg/.jpeg/.png/.gif/.webp) affichees en diaporama (3s par image) dans le panneau "Images" de /control. Sans rapport avec les snapshots CAM,SNAP du robot (voir page protocole) qui, eux, restent sur la Pi n1 dans camera/tmp/ — ce dossier-ci est une galerie manuelle, deposee a la main.
Robot mobile d'exterieur — page maintenue a la main, en parallele du code du site.
