Web Server Architecture

Overview of the robot-webserver project files (Raspberry Pi #2) and their dependencies, both on the code side and the network side. This page describes the web app; see the control protocol for details on the frames exchanged with the robot.

General dependency diagram

Two zones: what this repo runs on Pi #2, and what it talks to on Pi #1 (the robot repo, documented separately). A solid arrow means a direct Python import; a dashed arrow means a network call.

Raspberry Pi #2 — this repo (robot-webserver)
.env / .env.example —configures→ app.py
→ imports robot_link.py → imports nmea.py
→ serves (static) pages/*.html
→ serves (static) media/videos/, media/images/
generate_password.py —feeds (manual)→ .env
TCP 5050 (robot_link.py) ↓
HTTP 8000, /media/camera route (app.py) ↓
Raspberry Pi #1 — "robot" repo (documented separately)
link/server.py camera/stream_server.py

nmea.py is a deliberate copy of link/nmea.py from the robot repo (the two projects are deployed independently) — keep it in sync if the frame format changes, see the protocol page.

Application files

Site core (repo root)

FileRole
app.py Main Flask application: all routes (/login, /control, /pages, /api/send, /media/*), rendered as inline HTML (no templates/ folder). Handles session-based authentication, relays commands from the console to the robot via robot_link.send_command, and proxies the live camera stream from camera/stream_server.py. The /control page (status banner, two-tab Console/TCP console, command buttons) is built entirely server-side then animated with JavaScript. It is the site's single entry point: the other modules are only ever loaded by it.
robot_link.py Minimal TCP client: opens a connection to link/server.py (Pi #1), sends a frame, reads a response line, closes. Used by app.py in the /api/send route, itself called by the console and by the status banner's automatic polling. Builds the frame via nmea.build_sentence and parses it via nmea.parse_sentence. Always returns a dictionary with at least ok and sent, never lets an exception propagate up to Flask.
nmea.py Builds and parses $PROV,...*hh frames: build_sentence, parse_sentence, XOR checksum computation. Exact copy of link/nmea.py from the robot repo, with no external dependency. Used only by robot_link.py. See the protocol page for the full format.
generate_password.py Script to run by hand (python3 generate_password.py) to obtain the value of WEBSERVER_PASSWORD_HASH. Prompts for the password twice at the keyboard (never displayed), hashes it with werkzeug.security.generate_password_hash, and prints the line to paste into .env. Not imported by any other file in the project; the plaintext password is never written to disk.
requirements.txt List of the site's Python dependencies: flask, python-dotenv, requests. Installed with pip install -r requirements.txt. Deliberately short — unlike the robot repo, this site has no hardware dependency (GPIO, camera, serial port).
.env / .env.example Runtime configuration, .env is never committed (credentials, session key) — .env.example serves as a commented template. Read at startup by app.py via load_dotenv(): site credentials, the robot's address/port (ROBOT_HOST/ROBOT_PORT) and its camera's (CAMERA_PORT/CAMERA_STREAM_PATH).
.gitignore Excludes .env (secrets), venv/ and Python caches (__pycache__/) from the Git repo. Has no effect at runtime, only at commit time.

Static pages (pages/)

Served as-is by app.py (route /pages/<file>, no templating) so their own HTML/CSS never breaks; they automatically appear in the /pages listing as soon as an .html file is dropped into this folder.

FileRole
protocole_controle.html Living reference for the robot's command protocol (proprietary NMEA $PROV,... frames): frame types, examples, checksum. Updated with every change to the protocol on the link/server.py side of the robot repo.
rapport_rover_dgps.html Standalone project report (network diagrams for both sites, robot code organization, DGPS/PID/PWM pipeline, PID tuning curves). Generated at a given point in time, not automatically kept in sync with the rest of the code.
architecture_webserver.html This page — dependency diagram and role of each file in robot-webserver. To be updated whenever a file is added to or removed from the repo.

Media content (media/)

FolderRole
media/videos/ Videos (.mp4/.webm/.ogg/.mov) played one at a time in a loop in the "Video feed" panel of /control, only when the live camera stream is unavailable. Empty by default (just a .gitkeep) — shows a "coming soon" placeholder in that case.
media/images/ Images (.jpg/.jpeg/.png/.gif/.webp) shown as a slideshow (3s per image) in the "Images" panel of /control. Unrelated to the robot's CAM,SNAP snapshots (see the protocol page), which stay on Pi #1 in camera/tmp/ — this folder is a manual gallery, populated by hand.
Outdoor mobile robot — page maintained by hand, alongside the site's code.
